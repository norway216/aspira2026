### 2.2 关键认知

**OpenCV 的高层函数内部做了 20 年 SIMD 优化，永远优先使用它们而不是手写循环：**

```cpp
// ❌ 每帧浪费 ~10ms — 手写逐像素循环
for (int y = 0; y < size.height; ++y) {
    for (int x = 0; x < size.width; ++x) {
        float distToPupil = GeometryUtils::distance(pt, boundaries.pupil_center);
        if (distToPupil <= boundaries.pupil_radius) {
            pupilMask.at<uint8_t>(y, x) = 255;
        }
    }
}

// ✅ 每帧 ~0.05ms — 使用优化后的 OpenCV 函数
cv::circle(pupilMask, center, radius, cv::Scalar(255), -1);
```

### 2.3 不同 resize 插值方法的性能差异

| 插值方法 | 核大小 | 相对速度 | 适用场景 |
|---|---|---|---|
| `INTER_NEAREST` | 1×1 | 1× (最快) | 掩码、标签图 |
| `INTER_LINEAR` | 2×2 | 5× | **实时处理首选** |
| `INTER_CUBIC` | 4×4 | 10× | 高质量离线处理 |
| `INTER_LANCZOS4` | 8×8 | 30× | 最高质量、离线处理 |

## 4. 虹膜识别领域知识

### 4.1 Daugman 虹膜识别框架

这是本项目的基础理论框架，由 John Daugman 在 1993 年提出：

```
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ 眼睛检测  │──▶│ 虹膜分割  │──▶│ 归一化    │──▶│ 特征提取  │──▶│ 匹配     │
│ 定位眼睛  │   │ 分离虹膜  │   │ 极坐标    │   │ Gabor →  │   │ 汉明距离  │
│ ROI       │   │ 和瞳孔    │   │ 展开      │   │ IrisCode │   │ 决策     │
└──────────┘   └──────────┘   └──────────┘   └──────────┘   └──────────┘
```

### 4.2 各阶段的核心概念

| 阶段 | 概念 | 技术细节 |
|---|---|---|
| **归一化** | Daugman 橡皮片模型 | 将环形虹膜区域映射为矩形 (64×512)，用极坐标 (r,θ) 采样 |
| **特征提取** | IrisCode | 2D Gabor 小波相位量化 → 2048-bit 二进制编码 |
| **匹配** | 分数汉明距离 | `HD = ‖(codeA ⊕ codeB) ∩ maskA ∩ maskB‖ / ‖maskA ∩ maskB‖` |
| **旋转补偿** | 位平移匹配 | IrisCode 循环移位 ±16 bit，取最小距离（虹膜在图像中可能旋转） |
| **活体检测** | 多模态启发式融合 | 纹理分析 + 频域分析 + 镜面反射 + 运动检测 → 加权融合 |

### 4.3 推荐阅读

- Daugman, J. (1993). "High confidence visual recognition of persons by a test of statistical independence." *IEEE TPAMI*
- Daugman, J. (2004). "How iris recognition works." *IEEE TCSVT*
- Wildes, R. (1997). "Iris recognition: an emerging biometric technology." *Proceedings of the IEEE*

## 5. 深度学习与模型部署

### 5.1 模型格式与推理框架

| 知识点 | 具体内容 | 项目中的使用 |
|---|---|---|
| **ONNX 格式** | 开放神经网络交换格式，跨框架互操作 | YOLO 模型导出为 `.onnx` |
| **ONNX Runtime** | 微软的高性能推理引擎，支持 CPU/CUDA/ROCM | [OnnxRuntimeEngine](src/nn/OnnxRuntimeEngine.cpp) |
| **opset 版本** | ONNX 算子集版本，影响兼容性 | OpenCV 4.6 需要 opset ≤ 11 |
| **动态 vs 静态形状** | 动态 batch 维度 vs 固定尺寸 | `dynamic=False` 导出更快 |

### 5.2 YOLO 检测器知识

| 知识点 | 细节 |
|---|---|
| **YOLOv5 vs YOLOv8 输出格式** | v5: 3 个输出头 (基于锚框)；v8: 1 个输出 (无锚框) `[1, 4+nc, 8400]` |
| **输出解码** | 通道优先 (channel-major) 布局：`[fields, proposals]` → 需要转置/跨步访问 |
| **NMS (非极大值抑制)** | 贪心 IoU 滤波：按置信度排序 → 逐次排除重叠框 |
| **Letterbox 预处理** | 保持宽高比的缩放 + 灰色填充，避免图像变形 |
| **锚框 (Anchor boxes)** | YOLOv5 预定义的先验框尺寸，不同检测头使用不同尺寸的锚框 |

## 6. 性能优化

### 6.1 优化方法论

本项目中共应用了四种优化策略：

#### 策略 1: SIMD 向量化
**原则**: 永远不用手写循环处理像素，用 OpenCV 高层函数。

```cpp
// 手写循环 → SIMD 加速的 OpenCV 函数
cv::threshold(gray, binary, 40, 255, cv::THRESH_BINARY_INV);  // 一次比较 32 个像素
int count = cv::countNonZero(binary);                           // popcount 指令
```

#### 策略 2: 预计算与缓存
**原则**: 把"每帧相同"的计算提到初始化阶段。

```cpp
// 初始化时做一次
for (int orient = 0; orient < 8; ++orient) {
    m_gaborCache[orient].even = createGaborKernel(psi=0);
    m_gaborCache[orient].odd  = createGaborKernel(psi=π/2);
}

// 每帧直接用缓存
cv::filter2D(normalizedIris, response, CV_32F, m_gaborCache[orient].even);
```

#### 策略 3: 算法降级
**原则**: 用 O(N) 的轻量算子替代 O(N log N) 的重算子，保持功能意图。

```cpp
// 重：FFT O(N log N)
cv::dft(complexImg, complexImg);  // ~5ms

// 轻：Laplacian O(N)
cv::Laplacian(gray, lap, CV_32F); // ~0.05ms
// 两者都是高频能量检测器，在活体检测场景下功能等价
```

#### 策略 4: 数据结构选择
**原则**: 理解 STL 容器的复杂度差异。

| 操作 | `vector` | `deque` | 推荐 |
|---|---|---|---|
| `push_back` | O(1) 平摊 | O(1) | 两者均可 |
| `pop_front` / `erase(begin())` | O(n) | O(1) | **deque** |
| 随机访问 `[i]` | O(1) | O(1) | 两者均可 |

### 8.2 常见问题排查

| 问题 | 原因 | 解决方法 |
|---|---|---|
| 程序启动就崩溃 | 动态库找不到 | `ldd ./iris_app` 检查依赖 |
| ONNX Runtime 加载失败 | opset 版本不兼容 | 用 opset=11 重新导出模型 |
| 30 FPS 达不到 | 某阶段是瓶颈 | 用 `--benchmark-fps` 逐阶段计时 |
| YOLO 检测不到人脸 | 阈值太高或模型不对 | 降低 `confidence_threshold` 或换模型 |
| vector 换 deque 编译失败 | 函数签名没同步改 | 所有传递该参数的函数都要改 |
| Debug 构建下断点不准 | 优化等级太高 | 确认 `-O0` + `-fno-omit-frame-pointer` |

## 关键经验总结

> **1. 优先使用库函数，而非手写循环。**
> OpenCV 的一个 `cv::circle` 调用，比你写 65536 次 `sqrt` 的循环快 200 倍。这背后的 SIMD 优化是 20 年积累的成果。

> **2. 理解每个操作的复杂度。**
> `vector::erase(begin())` 是 O(n)，`deque::pop_front()` 是 O(1)。FFT 是 O(N log N)，Laplacian 是 O(N)。知道复杂度才能做正确的优化决策。

> **3. 预计算一切"输入无关"的东西。**
> Gabor 核只取决于方向参数，与输入图像无关 → 初始化时算好。如果每帧都在重新计算同样的东西，那一定是设计问题。

> **4. PIMPL 是管理第三方依赖的利器。**
> ONNX Runtime 的头文件有几千行；用 PIMPL 把它关在 `.cpp` 里，整个项目的编译速度不受影响，也不会泄漏类型到 API 层。

> **5. 先测量，再优化。**
> 用 `--benchmark-fps` 和 `FpsBenchmark::startStage/endStage` 精确定位瓶颈，而不是凭直觉猜测。

> **6. 深度学习不是万能药。**
> YOLO 改善了检测鲁棒性，但真正的性能瓶颈在 Gabor 卷积、Hough 圆检测和像素循环。用对数据结构和方法论，优化后的 Haar 流水线反而比 YOLO 流水线更快。
